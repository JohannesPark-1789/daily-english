## 2026-10-25 (일) — Actions 이관 뒤 첫 점검: 두 군데가 막혀 있었다

10-24 이관 후 실제로 도는지 확인하러 들어갔다가, **발송이 아직 한 번도 성공하지 못한 것**을 발견했다.
원인이 두 개였고 서로 무관하다.

### 1. 워크플로의 인자 전달 버그 (고침)

10-24 토요일 복습 발송이 12초 만에 실패해 있었다 (run 40043239322).

```
[FAIL] 주간 발송 실패 — Exception calling "ParseExact" with "3" argument(s):
       "String '-Force' was not recognized as a valid DateTime."
```

- **원인**: `$args = @('-Force')` 뒤 `& ./scripts/send-weekly.ps1 @args`.
  PowerShell 의 **배열 스플래팅은 값을 위치 인자로 넘긴다.** 그래서 문자열 `'-Force'` 가
  스위치 이름이 아니라 **첫 위치 인자인 `-Date`** 에 들어갔다. `$args` 가 자동 변수인 것도 겹쳤다.
- 로컬에서 같은 param 블록으로 재현 확인:

  | 방식 | 결과 |
  |---|---|
  | `$args = @('-Force')` → `@args` | `Force=False  Date='-Force'` ← 실패 |
  | `$p = @{ Force = $true }` → `@p` | `Force=True   Date=''` ← 정상 |

- **고침**: 두 워크플로 모두 해시테이블 스플래팅으로 바꿨다.
  더불어 입력값을 `${{ inputs.* }}` 로 스크립트 본문에 박던 것을 **env 경유**로 바꿨다
  (본문 삽입은 입력에 따옴표가 섞이면 그대로 코드가 된다).
- `-DryRun` 으로 세 경우(주간 스케줄 / 주간 날짜지정 / 평일 번호·강제지정) 전부 통과.
- **`weekly.yml` 은 매주 실패하는 상태였다.** 항상 `-Force` 를 붙이기 때문.
  `daily.yml` 은 스케줄 실행 때 `$args` 가 빈 배열이라 이 버그를 피해 갔고, **수동 실행에서만** 터졌다.

### 2. Secret 두 개가 빠져 있다 (사용자 작업 — 아직 안 됨)

```
등록됨 : KAKAO_REST_API_KEY · KAKAO_CLIENT_SECRET · KAKAO_REDIRECT_URI
필요함 : KAKAO_REST_API_KEY · KAKAO_CLIENT_SECRET · KAKAO_REFRESH_TOKEN · GH_PAT
```

- **`KAKAO_REFRESH_TOKEN` 없음** → 러너에 `state/tokens.json` 이 없으니(커밋 제외) 토큰을
  시작할 밑천이 없다. 버그를 고쳐도 **이것 없이는 발송이 안 된다.**
- **`GH_PAT` 없음** → 갱신 토큰 회전분을 Secret 에 다시 못 쓴다. 당장은 안 죽지만 2개월 뒤 조용히 멎는다.
- `KAKAO_REDIRECT_URI` 는 어느 워크플로도 쓰지 않는다. 둬도 해는 없다.
- 로컬 `state/tokens.json` 의 refresh token 은 **2026-12-21 까지 유효**하다 (10-23 발송 때 갱신된 것).

### 3. 알아 둘 것 — Actions 의 cron 은 정시가 아니다

10-24 실행은 예약(UTC 금 22:00 = KST 토 07:00)보다 **2시간 5분 늦은 KST 09:05** 에 떴다.
GitHub 이 부하에 따라 스케줄 실행을 미루거나(드물게) 거르는 것은 문서화된 동작이고, 고칠 방법이 없다.
"07:00 정각"이 필요하면 Actions 는 맞지 않는다. 아침에 받기만 하면 되는 용도라 그대로 둔다.

### 4. 해결 — Actions 첫 발송 성공 (22:55)

- 수정분 푸시 (`5ad4ca9`), 사용자가 Secret 2개 등록 → 네 개 전부 등록됨.
- **검증 방법**: `daily.yml` 대신 `weekly.yml -f date=2026-10-24` 를 돌렸다.
  실패했던 바로 그 경로를 밟으면서, 못 나간 토요일 카드를 되살리고, 진행 번호(050)를
  소진하지 않아 10-26 예약분이 밀리지 않는다.
- 결과 (run 40199787377, 19초):

  ```
  [DONE] 주간 복습 발송 완료 — 5문장 (45, 46, 47, 48, 49)
  갱신 토큰 변화 없음
  ```

- **카톡 도착까지 확인했다.** API 200 과 실제 수신은 다른 사실이라 따로 적는다.

- 실패 때 로그에서 `KAKAO_REFRESH_TOKEN:` 이 **빈칸**이던 것이 이번엔 `***` 로 찍혔다.
  빈칸 = 미등록이라는 해석이 맞았다. `GH_TOKEN` 도 `***`.
- "갱신 토큰 변화 없음"은 정상이다. 카카오는 만료가 가까울 때만 refresh token 을 새로 준다.
  회전 경로(`GH_PAT`)는 배선만 확인됐고 실제 회전은 12월 만료 즈음에 처음 돈다.

### 5. 카카오 토큰 만료 대비 예약

refresh token 유효기간은 2개월, 현재 만료는 **2026-12-22 07:11 KST**.
카카오는 **남은 기간이 1개월 미만일 때만** 새 refresh token 을 내려준다 (`kakao.psm1` 159~171행:

자동 갱신되고 워크플로가 Secret 에 덮어쓴다. 그 경로가 실패하면 12-22 에 조용히 멎는다.
