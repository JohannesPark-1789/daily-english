# 상세 설명 받아오는 프롬프트

ChatGPT 등에 `듣보잡영어_쇼츠_전체목록.md` 와 아래 프롬프트를 함께 넣는다.
받은 답변을 그대로 `data\notes\<범위>.md` 로 저장하면 `import-notes.ps1` 이 번호를 자동으로 붙인다.

> 30개씩 나눠 받는다. 한 번에 235개를 시키면 뒤쪽이 잘리거나 설명이 급격히 짧아진다.

---

## 프롬프트 (아래를 복사)

````
첨부한 목록은 영어 표현 235개다. 이 중 **1~30번**을 골라, 각 표현을 한국인 학습자가
"왜 그런 뜻이 되는지" 이해하도록 설명해 줘. 단순 번역이 아니라 감각을 잡아주는 글이어야 한다.

## 출력 형식 (반드시 지킬 것)

항목마다 이 순서로 쓰고, 항목 사이는 빈 줄로 구분한다.

1. **첫 줄은 영어 원문 한 줄.** 목록의 표현을 그대로 쓴다. 번호·기호·굵게 표시 없이.
2. **둘째 줄부터 `→` 로 시작하는 뜻.** 첫 번째 `→` 줄은 **가장 자연스러운 한국어 뜻 하나**만
   반말 회화체로 쓴다(이게 학습 카드의 정답면이 된다). 그 아래 `→` 줄에 상황별 대안을 덧붙여도 좋다.
3. **그다음부터 자유 서술.** 아래 설명 요령을 따른다.
4. **마지막 줄은 반드시 `핵심: ` 으로 시작하는 한 문장.** 40자 이내로, 이 표현의 감각을
   한 문장에 담는다. (이 줄이 매일 아침 카톡에 함께 나간다)

## 설명 요령

- 핵심 단어의 **기본 뜻에서 출발**해, 그것이 왜 관용적 의미로 굳었는지 사고 흐름을 보여준다.
- 한국어에 비슷한 사고방식이 있으면 연결한다.
- **혼동하기 쉬운 이웃 표현과 대조**한다 (예: won't vs wouldn't, 직역 vs 실제 쓰임).
- **짧은 대화 예시** 하나를 영어와 한국어로 보여준다.
- 설명은 존댓말, 카드 뜻(`→` 줄)과 `핵심:` 줄은 반말 회화체.
- 길이는 표현당 800~1500자.

## 하지 말 것

- 항목 앞에 번호나 `###` 같은 제목 기호를 붙이지 말 것.
- 표·코드블록·굵게 표시로 감싸지 말 것. 그냥 글로 쓴다.
- 본문에서 **다른 영어 표현을 인용할 때 줄 맨 앞에 단독으로 두고 다음 줄을 `→` 로 시작하지 말 것.**
  (자동 처리에서 새 항목으로 잘못 잘린다. `비슷한 표현: X / Y` 처럼 한 줄 안에 넣어라.)
- 목록에 없는 표현을 새로 만들지 말 것.

## 예시 (이 형식과 깊이를 그대로 따를 것)

I wouldn't count on it.
→ 난 그걸 너무 기대하진 않겠어.
→ 상황에 따라 "그건 장담 못 해." / "기대하지 마."

count의 기본 뜻은 '세다'입니다. 무언가를 count에 넣는다는 것은, 계획을 세울 때
그것을 확실히 있다고 보고 계산에 포함한다는 뜻으로 발전합니다.
You can count on me. 는 "계획을 세울 때 나를 확실한 전력으로 계산해도 돼"
→ "나는 믿어도 돼"가 되는 것이죠. 한국어의 "그 사람까지 머릿수에 넣고 계산해도 돼"와
비슷한 사고방식입니다.

그래서 count on it은 '그것을 확실한 것으로 계산하다' → '그게 일어날 거라고 믿고 계획하다'입니다.
여기에 부정을 붙인 I wouldn't count on it. 은 "나라면 그걸 확실한 것으로 계산에 넣지는 않겠다"가 됩니다.

왜 I won't가 아니라 I wouldn't일까요? wouldn't에는 If I were you 가 숨어 있습니다.
그래서 단정이 아니라 상대에게 건네는 조언·경고가 됩니다.

Do you think he'll come to the party? 걔 파티에 올 것 같아?
I wouldn't count on it. 글쎄, 기대 안 하는 게 좋을걸.

핵심: 그걸 '확실한 것'으로 치고 계획하진 마.

지금은 1~30번만 해줘. 끝나면 다음 30개를 요청할게.
````

## 왜 이런 제약이 붙었나

| 규칙 | 이유 |
|---|---|
| 첫 줄 = 영어 원문 | 번호가 없어도 목록과 대조해 자동으로 번호를 찾는다 |
| 첫 `→` 줄 = 뜻 하나만 | 카드 정답면에 그대로 들어간다. 여러 개를 나열하면 지저분해진다 |
| 마지막 `핵심:` 한 줄 | **매일 아침 카톡 본문**에 들어간다. 카톡은 200자 제한이라 40자를 넘기면 빠진다 |
| 다른 표현을 줄 단독으로 두지 말 것 | 그 줄이 목록에 있는 표현이면 새 항목으로 잘린다 (실제로 겪었다) |
| 30개씩 | 한 번에 다 시키면 뒤쪽 설명이 짧아지거나 잘린다 |

## 받은 뒤

```
data\notes\001-030.md 로 저장
  ↓
scripts\import-notes.ps1          번호 자동 대조, 뜻 후보 비교 (-ApplyMeaning 으로 반영)
  ↓
scripts\build-web.ps1             카드에 "자세히" 와 아침 메시지용 핵심 한 줄 반영
  ↓
git push                          사이트 반영
```
